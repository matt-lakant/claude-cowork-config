# Key Question Sharpener

## What this produces
A one-page problem statement: one key question, the decision it serves, success criteria, scope, stakeholders, and two alternate framings.

## Inputs to ask for
- The problem in the user's own words, and what triggered it now
- Who makes the final decision and by when
- The metric that would prove the problem is solved, with today's baseline
- Known constraints: budget, headcount, systems, regulatory, "off the table" options
If the decision owner or deadline is missing, ask once; if still unknown, write "[OWNER TBD]" or "[DATE TBD]" and flag it as the first risk.

## Method
1. Separate symptoms (what people observe) from the problem (the gap between current and target performance).
2. Name the decision. A key question that does not end in a choice someone must make is a research topic; rewrite until it does.
3. Draft the question in this form: "What must [owner] do to move [metric] from [baseline] to [target] by [date], within [constraints]?"
4. Test against five failure modes: too broad, solution embedded ("how do we implement a new ERP"), no metric, no owner, no date. Fix each hit.
5. Set scope: 3 to 6 items explicitly in and out (units, geographies, functions, horizon).
6. Write two alternates, one narrower and one wider, and state what each would miss.
7. List stakeholders who can block the answer and what each needs to believe.

## Output format
- Key question (one sentence, bold)
- Decision served, decision owner, deadline
- Success criteria table: Metric | Baseline | Target | Source
- In scope / Out of scope (two short lists)
- Alternate framings (2, with trade-off in one line each)
- Stakeholders: Role | Stake | What they need to believe
Maximum one page.

## Quality checks
- The question contains a metric, a target, an owner, and a date
- No solution is smuggled into the question
- Every baseline number traces to the user's input or is labeled an assumption
- The out-of-scope list is non-empty

## Notes from the source article
- **Replaces:** Week one of a strategy engagement: partner working sessions with the client until “margins are slipping” becomes one decision-ready question with an owner, a metric, and a date.
- **Example request:** “Field service costs are up and nobody agrees why. Turn that into the one question we should answer before the Q3 budget.”
- **What the user still owns:** Getting the decision owner to sign the question. A sharp question the CEO has not agreed to is still the wrong question.
- When handing the deliverable back, name in one line the decision above that stays with the user.
