# Vendor Selection Scorecard

## What this produces
A weighted scorecard, demo scripts, reference-call questions, and a scored comparison with a recommendation and negotiation points.

## Inputs to ask for
- Business requirements, prioritized if possible
- Vendor proposals or responses (attach PDFs)
- Demo notes or recording transcripts, if demos have happened
- Budget and timeline
- Security, integration, and compliance requirements
- If requirements are not prioritized, run MoSCoW (must, should, could, won't) with the user first

## Method
1. Set weighted criteria before seeing scores: functional fit, integration and technical fit, security and compliance, vendor viability, implementation approach, total cost, and user experience. Weights sum to 100.
2. Turn must-have requirements into pass or fail gates. A vendor that fails a gate is out, whatever its score.
3. Write demo scripts from real workflows using the company's own scenarios and sample data. Vendors present to the script, not their standard demo.
4. Score 1 to 5 with a written anchor per score level, citing where in the proposal or demo the evidence came from.
5. Compute five-year cost using each vendor's pricing at forecast volume, including implementation and escalators.
6. Write reference questions that probe implementation overruns, support quality, and what the customer would do differently.
7. Recommend a first and second choice, and list negotiation points from gaps found.

## Output format
- Criteria and weights table
- Gate results: Requirement | Vendor A | Vendor B | Vendor C
- Scorecard: Criterion | Weight | Scores per vendor with evidence reference
- Cost comparison, reference questions, and a recommendation under 250 words

## Quality checks
- Weights were fixed before scoring
- Every score cites evidence
- Gates are applied before weighted scores
- Cost uses the same volume assumptions for every vendor

## Notes from the source article
- **Replaces:** The software selection project: consultants writing criteria, scripting demos, scoring vendors, and running reference calls to produce a recommendation.
- **Example request:** “We have three proposals for a new field service management system. Here they are, plus our requirements list. Build the scorecard and the demo scripts.”
- **What the user still owns:** The final choice when scores are close, and the relationship with the vendor you pick for the next decade.
- When handing the deliverable back, name in one line the decision above that stays with the user.
